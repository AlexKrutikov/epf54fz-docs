# Настройка параметров обработки

## 1. Драйвер и версия

![](/images/image20.png)

[Использовать драйвер ККМ (для обработки АТОЛ)] --
используется для выбора используемой версии драйвера ККМ. Доступны
следующие варианты:

-   Версия 8.Х (COM-объект) - Для работы с ККТ будет использоваться
    драйвер ККМ версии 8

-   Версия 10.Х (COM-объект) - Для работы с ККТ будет использоваться
    драйвер ККМ версии 10

-   Версия 10.Х (Web-сервер) -- Работа с ККТ будет производиться
    посредством Веб-сервера Атол, к которому эта ККТ подключена

-   Версия 10.Х (JSON задания через COM-объект) -- Работа с ККТ будет
    вестись через драйвер 10 посредством отправки в него
    структурированных пакетных JSON запросов, таких же как при работе с
    веб-сервером. В этой ситуации драйвера сам интерпретирует такие
    пакетные запросы и транслирует их подключенной ККТ в виде отдельных
    команд на пробитие (открытие чека, регистрация позиции, регистрация
    оплат, закрытие чека...)

-   ККТ Штрих: Драйвер 4.Х - 5.Х (COM-объект) -- для работы с ККТ Штрих

-   ККТ Меркурий 115Ф, 119Ф, 130Ф, 180Ф, 185Ф (служба INECRMAN) -- для
    работы с ККТ Меркурий через службу INECRMAN

-   ВикиПринт (VikiDriver) -- для работы с Вики Принтами через
    VikiDriver.

-   Эмулятор -- Используется для отладки интеграции обработки и
    механизмов её работы, не связанных с отправкой данных в ККТ. Работа
    с драйверами при этом не ведется, а сформированный кассовый чек
    выводится на экран в табличный документ внутри отдельного
    диалогового окна.

[Таблица «Совместимая версия»] - предназначена для
добавления используемой версии драйвера ККТ в список совместимых, если
версия используемого драйвера отличается от версии требуемого драйвера,
но при этом работа на используемой версии происходит без проблем. Данное
добавление осуществляется путем нажатия правой кнопки мыши по таблице
Совместимых версий и позволяет избавиться от вывода сообщений о
несовместимости драйвера.

## 2. Параметры подключения

![](/images/image21.png)

В этом разделе задаются параметры связи с ККМ: порт, скорость обмена,
таймаут, IP адрес, IP порт.

[Порт] -- порт, к которому подключено устройство;

[Скорость] -- скорость обмена с устройством. Используется
только для подключения по интерфейсу RS-232 или USB с эмуляцией COM.

[Таймаут] -- время ожидания подтверждения приема команды.

[IP адрес] -- 1. Адрес ПК, к которому подключен ФР (при
работе с ФР по сети через службу управления драйверами); 2. Адрес ККМ
при подключении по интерфейсу Ethernet; 3. Адрес Веб-сервера Атол (при
работе через веб-сервер).

[IP порт] -- 1. Порт на ПК, настроенный для доступа к нему
по сети (при работе с ФР по сети через службу управления драйверами); 2.
Порт ККМ, настроенный в аппарате при подключении по интерфейсу Ethernet;
3. Порт Веб-сервера Атол.

[Таймаут ожидания ответа от WEB-сервера (секунд)] --
максимальное количество секунд ожидания ответа от веб-сервера, после
посылки в него команды на фискализацию чека, печать отчета и прочее.

**Для обработки Штрих, состав набора параметров подключения немного
отличается:**

![](/images/image22.png)

[Тип подключения] -- указывается вариант подключения ККМ к
компьютеру.

Доступные варианты:

-   локально - для подключения по USB/COM),

-   Сервер ККМ (TCP) - для подключения через ПО «Сервер ККМ» по TCP
    (платная лицензия),

-   Сервер ККМ (DCOM) - для подключения через ПО «Сервер ККМ» по DCOM
    (платная лицензия),

-   Эмулятор - режим эмулятора драйвера,

-   ТСР-сокет -- для подключения по RNDIS или по локальной сети.

[Протокол обмена] -- Выбирается протокол для работы с ККМ
(Стандартный или Протокол 2.0)

[Параметры Порт, Скорость, Таймаут, IP Адрес, IP порт] --
идентичны параметрам обработки Атол.

## 4. Параметры устройства

![](/images/image27.png)![](/images/image28.png)

[Пароль пользователя] -- пароль пользователя в ККМ, от имени
которого будут выполняться операции в форме обработки.

> Если конфигурация 1С не поддерживает установку пароля кассира ККМ в
> параметрах пользователя (например, 1С Розница 1.0, [см. подробнее
> здесь](/instructions/user-params)), то
> данный пароль используется для проведения операций на ККМ, таких как:
> открытие чека, закрытие чека, аннулирование чека, снятие отчетов без
> гашения и с гашением и т.д.

[Пароль устройства] -- пароль доступа к ККМ. На фискальных
регистраторах фирмы Атол по умолчанию пароль доступа к ККМ не
установлен. Поэтому в обработке это значение равно 0.

Для ККМ Штрих этот пароль имеет значение 30.

Оба описанные выше параметра используются для проведения теста связи в
форме настройки обработки и проведения тех операций по снятию отчетов,
которые так же доступны из формы настройки обработки.

Для проведения операций пробития чеков, снятия отчетов из других мест
конфигурации (например, из документа «Чек ККМ» или «Приходный кассовый
ордер») используется пароль, указанный в настройках пользователя
(подробнее см. в разделе «[Установка параметров пользователя для работы
с ККМ](/instructions/user-params)»).

[Проверять соответствие выбранной модели в 1С модели ККМ] -
актуально для обработки Атол и использования драйверов версии 8, когда
две разные модели могут работать под одним и тем же номером протокола.
Установка этого флага позволит избежать ошибки драйвера 8 о
несоответствии модели ККТ.

## 5. Параметры наличной оплаты

![](/images/image29.png)

Данные параметры используются для пробития чеков из документов
«Приходный кассовый ордер» и «Расходный кассовый ордер». Для включения
возможности пробития их этих документов необходимо включить параметр
«Наличная оплата» и выбрать номер секции, на которую будет происходить
пробитие чеков.

[Всегда брать секцию из данной настройки, а не из склада] --
При пробитии розничных чеков секция будет передаваться из этой
настройки, а не из склада, как это заложено поумолчанию в конфигурации
при пробитии розничных чеков.

## 7. Передавать налоговые ставки в ККМ по каждому товару из документа

![](/images/image33.png)

Включение данной настройки позволяет регистрировать налоги для товарных
позиций в чеке ККМ. Данный флаг устанавливается автоматически при
первоначальном подключении обработки и снимать его не рекомендуется.

Ниже под данным флагом располагается таблица соответствия ставок налогов
в 1С ставкам налогов в ККМ. В большинстве случаев заполнять данную
таблице нет необходимости.

Исключение составляют случаи, когда необходимо пересопоставить ставки из
программы 1С со ставками в ККМ (например, в соответствие ставке НДС 18%
установить ставку НДС 18/118 в ККМ вместо ставки 18%).

Так же в некоторых конфигурациях за передачу налогов в товарные позиции
отвечает настройка, которая расположена в настройках пользователя
(подробнее см. в разделе «[Установка параметров пользователя для работы
с ККМ](/instructions/user-params)»).

## 8. Ставка «Без НДС» для всех товаров

Позволяет для всех пробиваемых
товаров использовать ставку НДС «Без НДС» не зависимо от того, какая
    ставка передается из программы по позициям. Данный флаг работает
    только совместно с флагом «Передавать налоговые ставки в ККМ по
    каждому товару из документа»

## 9. Алгоритм обработки ставки «НДС 18%» при возврате товара в 2019 году

Если в 2019 году оформить возврат со ставкой НДС 18% стандартным
образом, то без данного алгоритма такой возврат пробьётся по ставке НДС
20% вместо 18%. Данный алгоритм позволяет установить поведение обработки
при оформлении возвратов в 2019 году, когда ставка НДС 18% поменяется на
20%.

Доступны 4 варианта работы алгоритма:

1)  Проводить по ставке 18% с выбором

2)  Проводить по ставке 20% с выбором

3)  Проводить только по ставке 18%

4)  Проводить только по ставке 20%

Первый вариант по умолчанию будет проводить возврат по ставке 18% в КММ,
если и в документе возврата установлена ставка НДС 18%. При этом в форме
Менеджера чека будет доступен и по умолчанию установлен флаг
«Использовать ставку НДС 18».

![](/images/image34.png)

Второй вариант будет по умолчанию проводить возврат по ставке 20% в ККМ,
если в документе возврата установлена ставка НДС 18% и в Менеджере чека
будет доступен и по умолчанию снят флаг «Использовать ставку НДС 18».

Использование 3го и 4го вариантов аналогичны первому, но при этом в
Менеджере чеков флаг «Использовать ставку НДС 18» будет недоступен для
установки или снятия. Также при варианте алгоритма №3 флаг будет
установлен, а при варианте алгоритма №4 - флаг будет снят.

Поведение данного алгоритма не зависит от настроек открытия Менеджера
чека и будут срабатывать даже при отключенном Менеджере чеков.

## 10. Скидки

![](/images/image35.png)

Данная настройка управляет возможностью печати скидок в кассовом чеке.

Возможны следующие варианты:

1.  Не печатать -- при данной настройке скидки в чеке печататься не
    будут

2.  Печатать после каждой строки товара -- скидки будут печататься после
    каждой позиции, к которой применена скидка.

3.  Печатать все в конце чека по товарам -- список примененных в чеке
    скидок будет печататься в конце чека.

4.  Печатать в конце чека свернуто -- в конце чека будет печататься
    общая сумма всех примененных на позиции скидок.

5.  Скрывать все скидки/надбавки -- все скидки или наценки будут скрыты,
    цены будут установлены таким образом, чтобы в чеке не отображалось
    скидок/наценок.

## 11. Дополнительные настройки

**Атол**

![](/images/image36.png)

**Штрих**

![](/images/image37.png)

[Ограничение наименования товара (символов)] -- позволяет
задать число первых символов от наименования, которое будет передаваться
в ККМ при пробитии чека.

[Нумерацию чеков брать из свойства] -- определяет из какого
счетчика в ККТ брать номера кассового чека, который записывается в
документ в 1С. Рекомендуемое значение: «Номер ФД из фискального
накопителя».

[Проверять датчик чековой ленты] -- данная настройка
присутствует в обработке для ККМ Штрих и позволяет контролировать
наличие чековой ленты при пробитии чеков. Если чековая лента закончится
в процессе пробития чека, то обработка будет ожидать, пока не вставят
новый рулон чековой ленты, после чего продолжит печать.

[Использовать программный отрез при пробитии нефискальных
чеков] -- активирует отрезку чека после печати нефискального
чека (например, после банковского слипа).

[Тип программного отреза при нефискальной печати] --
определяет какой тип отреза чековой ленты применять при программном
отрезе чековой ленты. Доступные варианты: Полный отрез и частичный
отрез.

[Количество строк промотки перед отрезом чека] --
проматывает чековую ленту на указанное число строк перед программным
отрезом.

## 12. Открытие/ закрытие смены и проверка статуса смены

![](/images/image38.png)

[Использовать работу с документом «Кассовая смена»] - опция
предназначена для использования записи информации в документ «Кассовая
смена» при открытии и закрытии смены через внешнюю обработку «Работа с
кассой». Подробнее смотри [в разделе по работе с данной
обработкой](/instructions/cash-register-ext).

[Проверять статус смены в ККМ перед печатью чека] --
активирует функционал проверки статуса смены перед пробитием чека. Если
смены превысила 24 часа, то пробитие чека прерывается и ожидается что
пользователь закроет кассовую смену.

[Автоматически закрывать смену перед печатью чека при превышении 24
часов] -- активирует функционал автоматического закрытия
смены и открытия новой смены, если при перед пробитием определилось, что
смена превысила 24 часа.

## 13. Лог драйвера

В драйвере Атол ведение лога активировано по умолчанию и дополнительных
действий по включению ведения лога производить не требуется.

В драйвере Штрих ведение лога по умолчанию не ведется и может быть
включено дополнительно. Для этого в обработках для ККМ Штрих добавлена
опция включения ведения лога, а также возможность указания пути, по
которому будет располагаться файл лога.

## 14. Пробитие чеков ПКО, РКО, ОПК, Чек ККМ

![](/images/image40.png)

[Получать дополнительную информацию из конфигурации при пробитии чеков
из ПКО/РКО/ОПК и прочих платежных документов] - Данная
настройка активирует функционал получения дополнительной информации из
конфигурации по документам ПКО/РКО/ОПК и прочим платежным документам, из
которых инициирован процесс печати чека. Данная опция важна для
правильного заполнения параметров чека всеми необходимыми реквизитами
для версии ФФД 1.05 и выше.

[Выводить стандартный текст из ордеров («Принято от...»)] --
данная настройка отвечает за вывод в чеке стандартной информации из
кассовых ордеров - информации от кого принят платеж и на основании чего
(поле Основание в документе).

Подробнее о пробитии чеков из этих документов описано в разделе
"[Пробитие чеков из кассовых
ордеров](/instructions/cash-orders)".

[Заменить контрагента в нефискальной строке \"Принято от\...\" на своё
наименование] -- В стандартной строке «Принято от...» вместо
наименования контрагента выводит свой произвольный текст.

[Получать дополнительную информацию из конфигурации при пробитии чеков
из документа Чек ККМ (и режима РМК)] -- определяет будет ли
чек ККМ обрабатываться дополнительно для получения из базы данных
информации о документе и товарных позициях документа. Включение данной
опции позволяет правильно определить предмет расчета для товарных
позиций при работе по ФФД 1.05 и выше, а также получить информацию из
документа для механизма «разделения по СНО», в случае его использования.

## 16. Механизм определения документа печати

![](/images/image42.png)

При пробитии чека в типовых конфигурациях 1с в обработку обслуживания не
поступает информации, из какого документа происходит данное пробитие. По
этой причине затруднено получение информации о товарных позициях
документа отгрузки/заказа, на основании которого выписан кассовый ордер,
ведь для начала неплохо было бы знать из какого именно кассового ордера
происходит пробитие и далее можно получать информацию из документов
основания, документов сделки, документов расчета.

Данная опция активирует поиск документа, из которого происходит печать
чека, по журналу регистрации, что решает проблему получения информации о
товарных позициях для чека.

## 17. Настройки «Менеджера чека»

«Менеджер чека» --- это дополнительное окно обработчика чека,
открывающееся при пробитии чека из кассовых ордеров и прочих платежных
документов. Это окно позволяет управлять операциями чека перед выводом
чека на печать.

![](/images/image43.png)

Данный блок настроек относится к функционалу менеджера чека.

[Автоматически распределять сумму платежа при частичной предоплате и
оплате кредита] -- при частичной предоплате и оплате
кредита, сумма кассового ордера является лишь частью оплаты товаров.
Поскольку в данных операциях предметом расчета является «Платеж», то
сумму платежа, как правило, требуется распределить по конкретным
платежам за товары. Включение данной опции активирует автоматическое
пропорциональное распределение общей суммы платежа по платежам за каждый
товар. Более подробно об операциях предоплаты и оплаты кредита [см.
раздел.](/instructions/ffd105)

[Разрешить ручное управление видом операции в «Менеджере чека» для ФФД
1.05] -- Данная настройка активирует возможность ручного
выбора [операции](/instructions/ffd105) при пробитии чека в формате фискальных
данных 1.05 и выше. При этом в менеджере чеков всегда станет доступной
верхняя панель с меню выбора операции, с помощью которого можно
переключить один вид операции на другой.

![](/images/image44.png)

Эта настройка актуальна, например, в следующих ситуациях:

1.  Когда взаиморасчеты с клиентом ведутся по заказам и без разреза по
    документам расчетов.

В такой ситуации при выписывании Заказа от покупателя, далее на
основании него Реализации, отражающей факт полной отгрузки и затем на
основании Реализации -- Приходного кассового ордера, отражающего факт
полной оплаты отгрузки в Менеджере чека, отобразится операция «Полная
предоплата» вместо предполагаемой «Отгрузка с полной оплатой».
Произойдет так потому, что в Приходном кассовом ордере не будет
зафиксирован документ расчетов из-за условий договора с контрагентом.

2.  На предприятии установлен запрет отгрузки без оплаты, и сотрудники
    вынуждены выписывать сначала кассовый ордер на сумму оплаты, а
    следом реализацию, т.к. только после оплаты допускается формирование
    отгрузочных документов. В этой ситуации так же в Менеджере чека
    изначально отобразится операция «Предоплата полная/частичная»,
    которую можно будет переключить на «Отгрузку с полной/частичной
    оплатой».

[Не распределять позиции чека как платежи при полной предоплате и полной
оплате кредита (кода сумма сделки равна сумме платежа)] -- В
стандартном механизме пробития предоплат реализован механизм, когда
товарные позиции из документа сделки выводятся в чек преобразованные в
Платежи для отражения платежа по товарам в качестве предмета расчета. В
данном механизме количество платежа всегда устанавливается равным 1, а
сумма платежа устанавливается равной сумме позиции чека. Указанное
преобразование количества и цены производится как для полной предоплаты,
так и для частичной, а также для любой оплаты кредита. Данная опция
позволяет не производить преобразования количества и цены для позиций с
платежами для операций «Полная предоплата» и «Оплата кредита» когда
сумма принимаемого платежа равна общей сумме сделки. Таким образом
платежи в позициях чека будет фигурировать с теми же количествами и
ценами что и товарные позиции в документе сделки.

[Контролировать взаиморасчеты по сделкам] -- данная опция
предназначена для активации механизма анализа предыдущих оплат по
сделке. Благодаря чему обработка будет сама заполнять суммы предоплат в
чеке и автоматически определять, когда нужно провести платеж по
реализации как частичный расчет с передачей в кредит, а когда как оплату
кредита.

Анализ предоплат работает по таким типам ведения взаиморасчетов по
договорам как «По счетам», «По заказам», «По договору в целом». В
последнем варианте необходимо вручную отражать предоплаты в документе
Реализации на закладке «Предоплата», которая в свою очередь доступна при
установленном флаге в свойствах договора «Вести по документам расчетов с
контрагентами».

> **Сделки по договорам без установленного флага «Вести по документам
> расчетов с контрагентами» не анализируются на предмет поступления
> предыдущих платежей по причине того, что сама конфигурация при этом не
> контролирует взаиморасчеты в разрезе документов.**

## 18. Информация в чеке при частичной оплате

![](/images/image45.png)

Данный блок настроек определяет, какое наименование фискальной позиции в
чеке будет выводиться при частичной оплате товара. По умолчанию
преднастроен вывод слова «Аванс» при продаже, «Возврат Аванса» -- при
возврате от покупателя, «Оплата» -- при пробитии чека покупки (Расхода),
«Возврат Платежа» -- при пробитии чека возврата покупки (Возврата
расхода). Эти значения можно изменить по своему усмотрению.

Флаг «Добавлять содержимое поля «основание» в фискальную строку --
определяет добавление в наименование фискальной позиции в чеке
содержимое одноименного поля «Основание» в кассовом ордере.

Для примера: итоговая фискальная строка, при настройках, указанных на
скриншоте выше, может выглядеть следующим образом:

![](/images/image46.png)![](/images/image47.jpeg)

![](/images/image48.png)

При включении флага «При частичной оплате, оплате кредита из ПКО/РКО/ОПК
добавлять к наименованиям товаров следующие префиксы» к наименованиям
товаров в чеке будут добавлены префиксы в начале «Предоплата за» - при
частичной или полной предоплате и «Оплата кредита за» - при оплате
кредита за ранее отгруженный товар.

Согласно документу Форматы Фискальных Данных данные префиксы выводить не
обязательно, а вместо них можно указывать в чеке Способ расчета для

суть способа расчета за эти товары.

## 21. Нефискальная печать

![](/images/image56.png)

Данные механизм предназначен для настройки вывода на бумажном чеке своих
произвольных нефискальных строк (данные строки не передаются в ОФД в
составе электронного чека), которые могут быть сформированы из
произвольного готового текста или по своему алгоритму на встроенном
языке 1С.

Под нефискальные строки в чеке отводится 4 области:

1.  Шапка чека

2.  Подвал чека

3.  Текст непосредственно перед фискальной строкой чека

4.  Текст сразу после фискальной строки чека.

Пункт 3 и 4 применим к каждой позиции чека. Для каждой области отведена
своя таблица с выводимыми в этой области строками.

При добавлении строки в одну из 4х таблиц необходимо указать следующие
данные:

1.  Тип строки (текст или свой алгоритм),

2.  Текст стоки (сам текст или код на языке 1С),

3.  Выравнивание (По центру, по левому или по правому краю),

4.  Перенос (тип переноса строк -- не переносить, переносить по словам,
    переносить посимвольно).

Ввод текста для текстовых строк осуществляется в форме ввода
произвольного текста, которая вызывается по кнопке с тремя точками в
колонке «Текст строки» для строки с типом «Текст».

![](/images/image57.png)

По завершению ввода текста в этом окне необходимо нажать на кнопку «ОК»
и введенные данные сохранятся в таблице. При необходимости отказа от
ввода нужно нажать на кнопку «Закрыть».

Ввод произвольного алгоритма на встроенном языке осуществляется в форме
ввода произвольного кода, которая вызывается по кнопке с тремя точками в
колонке «Текст строки» для строки с типом «Свой алгоритм».

![](/images/image58.png)

В открывшемся окне необходимо заполнить код на встроенном языке 1С. Для
простоты заполнения кода доступна контекстная подсказка в правой части
окна, а также два примера кода (кнопка «Примеры кода»). Также как и для
формы ввода текста в данном окне кнопка «ОК» выходит из режима ввода
кода с сохранением данных в таблицу, а кнопка «Закрыть» предназначена
для выхода без сохранения данных.

пользователю будет выведено предупреждение с информацией о том, что

[Критичный срок до окончания действия ФН (дней)] --
количество дней до окончания срока действия фискального накопителя, при

Существует 3 режима работы настроек кассиров:

## 25. Разделение чеков по СНО

Функционал разделения чеков по Системам Налогообложения предназначен для
предприятий, совмещающих в работе несколько систем налогообложения в
зависимости от вида реализуемых товаров/услуг или иных факторов. Сама
необходимость именно разделения чеков связана с тем, что в одном чеке
может быть представлена только одна СНО и не более. Т.е. при совмещении
СНО и одновременной реализации товаров/услуг, соответствующих разным
СНО, в одном чеке не отразить оба варианта СНО. Возникает необходимость
пробития отдельных чеков для каждой системы, но стандартный функционал
типовых конфигураций и обработок не позволяет это реализовать.

![](/images/image76.png)

> Для возможности полноценного использования разделения по СНО
> необходимо, чтобы при регистрации кассового аппарата были указаны все
> системы налогообложения, которые будут задействованы при реализации
> тех или иных товаров/услуг.

Первым делом, для использования функционала разделения по СНО,
необходимо в настройках обработки на закладке «ФЗ-54» установить СНО по
умолчанию (параметр «Система налогообложения») и значение должно
отличаться от значения «не передавать реквизит». Так же необходимо
включить флаг «Использовать разделение чеков по системам
налогообложения» на закладке «Разделение по СНО».

Установленный СНО по умолчанию будет использоваться как стандартный СНО
для всех реализуемых товаров и услуг. Для всего остального необходимо
установить «правила-исключения» в таблицах разделения по СНО. Другими
словами -- все то, что настроено в таблицах будет пробиваться по той
системе налогообложения, которая будет указана в этих же таблицах, а все
остальное, что не указано в таблицах, будет пробиваться по системе
налогообложения, установленной на закладке ФЗ-54.

Таким образом, нет необходимости настраивать таблицы для всех товаров
или операций без исключения, а добавить лишь в предлагаемых таблицы те
самые исключения, которые будут пробиваться по отличной от установленной
по умолчанию СНО.

Всего доступно 7 вариантов разделения чеков по СНО:

-   По номенклатуре

-   По свойствам номенклатуры

-   По видам номенклатуры

-   По номенклатурным группам

-   По складам

-   По документам

-   По организациям

Последние 2 варианта действуют в целом на операцию пробития. Все
остальные -- на конкретные товары из пробиваемого на ККМ документа.

    проверки.

-   Так же можно установить действие обработки при отсутствии ответа от
    ГИС МТ и от локального модуля честного знака -- запретить продажу,
    спросить у кассира, разрешить продажу. Варианты «спросить у кассира»
    и «разрешить продажу» допускается использовать только для целей
    отладки и тестирования. В боевом режиме возможно только указание
    варианта «Запретить продажу», чтобы не допустить нарушения ППРФ 1944
    и не осуществить продажу товара с отклонениями.
