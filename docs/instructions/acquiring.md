# Эквайринг

Обработка умеет проводить безналичную оплату через банковский платёжный терминал,
подключённый к кассовому компьютеру. При пробитии чека сумма безналичной оплаты сначала
списывается по терминалу, и только после успешной оплаты пробивается фискальный чек;
слип терминала печатается на ленте кассы. Поддерживаются возврат оплаты, автоматическая
отмена при сбое пробития чека и сверка итогов при закрытии смены.

Поддерживаемые платёжные системы:

| Платёжная система | Что нужно на кассовом компьютере |
|---|---|
| Сбербанк | библиотека Сбербанка (SBRFCOM) |
| DualConnector *(бета)* | установленное ПО DualConnector |

## Подключение терминала

Терминалы подключаются в настройках обработки на закладке «Эквайринг». В таблице терминалов
у каждой строки:

- **Активен** — выключенный терминал в операциях не участвует;
- **Наименование** — произвольное название для кассира и настроек;
- **Тип платёжной системы** — Сбербанк или DualConnector;
- **Код** — числовой ключ строки, заполняется автоматически. По коду на терминал ссылаются
  условия применения, поэтому терминал можно переименовывать и переставлять в списке —
  условия не сломаются.

Кнопка «Настройка параметров» открывает форму параметров выбранного терминала — свою
для каждой платёжной системы (см. ниже).

## Когда применяется эквайринг: условия

До версии 6.0.1 оплата по терминалу шла всегда, когда в списке был хоть один активный
терминал. Теперь под списком терминалов есть таблицы условий — по пользователям,
организациям, типам документов, складам и контрагентам. В каждой строке условия выбирается
терминал, на котором проводить оплату.

- **Все таблицы пусты** — поведение прежнее: оплата идёт на первом активном терминале.
- **Хоть одна таблица заполнена, но чек ни под одно условие не подошёл** — эквайринг
  не применяется, чек пробивается как обычно.
- **Значение «&lt;не применять&gt;»** в колонке «Терминал» выключает эквайринг для
  подходящих чеков. Так выражается исключение: «применять везде, кроме организации X».
- **Приоритет при нескольких совпадениях** (от низшего к высшему): контрагент →
  организация → тип документа → склад → пользователь. Совпадение по пользователю
  перекрывает все остальные.
- **Вкладка «Свой алгоритм»** — если условий таблицами не хватает (например, нужно
  смотреть на состав чека), включите флажок и напишите код: он должен заполнить переменную
  `Терминал` кодом строки терминала, 0 — не применять. При включённом флажке таблицы
  не проверяются.

## Как проходит оплата

1. При пробитии чека с безналичной оплатой обработка выбирает терминал по условиям
   и проводит оплату. Терминал запрашивает карту, печатается слип.
2. После успешной оплаты пробивается фискальный чек.
3. Если чек после успешной оплаты не пробился, обработка **автоматически отменяет оплату**
   по тому же терминалу и печатает слип отмены. Деньги покупателю возвращаются, чек можно
   пробить заново после устранения причины отказа.
4. Если автоматическая отмена не удалась, кассир получает окно с суммой, названием
   терминала и номером ссылки (RRN) — операцию нужно отменить на терминале вручную.
   Подробнее — в разделе [«Известные проблемы»](/instructions/troubleshooting).

Терминал участвует только в **оплате и возврате оплаты**. Чеки расхода, возврата расхода
и чеки коррекции пробиваются без обращения к терминалу: такие расчёты проходят переводом,
через СБП или иным способом вне эквайринга.

## Сверка итогов при закрытии смены

При снятии Z-отчёта обработка выполняет сверку итогов по каждому активному терминалу.
Если сверка не прошла (терминал выключен, отвязан, на обслуживании), кассиру задаётся
вопрос: продолжить закрытие смены без сверки или прервать его. Ответ «Да» закрывает
смену кассы — сверку в этом случае нужно выполнить на терминале отдельно.

## Параметры терминала Сбербанка

- **Ширина слип-чека** и **количество копий слипа** — как печатать слип на ленте кассы.
- **Номер отдела** — необязательный параметр для терминалов, зарегистрированных
  на несколько отделов (мерчантов). Когда выбран отдел, оплата и возврат проводятся
  по нему. Несколько строк терминалов с разными отделами на одном физическом терминале
  в сочетании с условиями по организациям дают мультимерчант: каждая организация
  проводит оплату по своему мерчанту.
- **Разрешить отмену без карты** — автоматическая отмена оплаты не будет требовать
  повторного предъявления карты покупателя. Флажок работает, только если на терминале
  со стороны банка включена опция «Операции без карты по номеру чека или ссылке».
- **Тест связи** — запрашивает у терминала номер терминала и мерчанта. Позволяет
  проверить связь без финансовой операции.

## DualConnector (бета)

DualConnector — программное обеспечение интеграции с платёжными терминалами,
устанавливаемое на кассовый компьютер. Обработка работает с ним напрямую, без
дополнительных компонент 1С. Поддержка помечена как **бета**: оплата, возврат, отмена,
сверка итогов и печать слипа реализованы, идёт накопление обратной связи с живых
терминалов.

Форма параметров терминала показывает, установлено ли ПО DualConnector на этом
компьютере, и содержит:

- **ID терминала**;
- **Порт терминала** — 0 для подключения по сети, 1–32 для COM-порта с этим номером;
- **Скорость обмена** (для COM-подключения);
- **Код валюты** (по умолчанию 643 — рубль);
- **Вариант отмены при ошибке чека** — как отменять оплату, если чек после списания
  не пробился: отменой платежа или возвратом платежа (для терминалов, где отмена
  запрещена банком);
- **Диагностический режим** — вывод полей запросов и ответов терминала в служебные
  сообщения, для разбора проблем;
- ширину слип-чека и количество копий слипа — как у Сбербанка.

Кнопка «Тест связи» выполняет короткий обмен с терминалом без финансовой операции.
При любой ошибке обработка показывает развёрнутое сообщение: этап операции, код и
описание ошибки — эти сведения стоит приложить к обращению в поддержку.
