# Разрешительный режим

## Введение
С 1 апреля 2024 года поэтапно вводится режим проверок на кассах для
товаров, подлежащих маркировке для следующих категорий: табак, пиво,
молочная продукция, упакованная вода, антисептики, БАД, обувь,
фотоаппараты, шины, одежда, духи и безалкогольные напитки.

С этой даты поэтапно наступает запрет продажи товара, подлежащего
обязательной маркировке, если при проверке кода маркировки на кассе
кассовое ПО выдало ошибку. Изменения будут направлены на улучшение
контроля за товарооборотом на рынке, усиление борьбы с контрафактной
продукцией и повышение защиты прав потребителей.

Более подробной информацией по разрешительному режиму можно ознакомиться
на сайте:
<https://markirovka.ru/community/rezhim-proverok-na-kassakh/rezhim-proverok-na-kassakh>

**Обработка полностью поддерживает все требования по работе с
разрешительным режимом в связке с программным модулем «Айтида iMark»**

## Что такое Айтида iMark?
Айтида iMark -- это программный модуль, подключаемый к популярным
кассовым решениям и обеспечивающий взаимодействие с ГИС МТ в части
работы с разрешительным режимом согласно всем необходимым для этого
требованиям.

Среди функциональных возможностей модуля присутствуют:

\- **Открытый API для интеграции**. Это позволяет подключить и
использовать модуль совместно с любым кассовым решением.

\- **Возможность работы с несколькими юридическими лицами** для
разделения проверок по своим для каждого юридического лица токенам,

\- **Работа с собственной базой данных** SQL Lite и MS SQL Server, а
также автоматическое пополнение базы проданных кодов маркировки для
последующего исключения повторных продаж без необходимости отправки
запроса проверки в ГИС МТ

\- **Автоматическое резервное копирование** базы данных с заданным
интервалом для повышения уровня надежности.

\- **Автоматическая фоновая работа с CDN**: получение списка, проверка
доступности, расчет скорости отклика, актуализация и переключение между
CDN для наиболее быстрого получения результата проверки. Полное
соответствие требованиям к поведению ПО в случае аварийных ситуаций,
описанных в методических рекомендациях Честного знака в пункте «1.4.3.
Переключение между CDN-площадками», доступно начиная с релиза 1.02.

\- **Разграничение прав доступа** пользователей по ролям. Это позволит
выдавать ограниченный доступ к API и обезопасить систему от необдуманных
действий сотрудников.

\- **Удобный клиент для управления** и настройки сервера iMark. Варианты
взаимодействия с сервером: 1) API; 2) Приложение для Windows; 3) Веб
интерфейс (скоро).

\- **Ведение журнала** клиентских вызовов и журнала взаимодействия с ГИС
МТ для обеспечения наличия технической информации и выполнении
требования ППР 1944 в случае сбойных ситуаций (отсутствие интернета,
сбой со стороны ГИС МТ...)

\- **Автоматическое обновление** встроенных модулей взаимодействия с ГИС
МТ. В случае изменения алгоритмов взаимодействия с ГИС МТ, не требующих
изменений в ядре службы, не потребуется вручную обновлять файлы службы.
Все изменения загрузятся в модуль iMark автоматически с нашего сервера.

## Подготовка и настройка
1)  Произвести доработку конфигурации, согласно руководства «Инструкция
    по модулю Маркировка.pdf», входящего в состав поставки. В частности,
    требуется добавить новый реквизит в табличную часть документа ЧекККМ
    для хранения идентификатора запроса и времени запросам в ГИС МТ для
    их последующей передачи в чек.

2)  Скачать актуальную версию модуля iMark и руководство администратора
    по ссылке: <https://itida.ru/itida-imark>. Согласно разделу 3
    руководства администратора установить и настроить модуль iMark.

3)  Обновить обработку как минимум до версии 5.1.3.

4)  Подключить ККТ, зарегистрированную под ФФД 1.2. Прошивку и драйвер
    обновлять как правило не требуется.

5)  В настройках обработки переключить версию ФФД для работы на значение
    ФФД 1.2.

![](/images/image124.png)

6)  В настройках обработки на вкладке Маркировка -- Разрешительный режим
    активировать флаг «Включить функционал работы по разрешительному
    режиму»

![](/images/image125.png)

Указать IP адрес сервера iMark, Порт iMark (по умолчанию равен 8000) и
пароль пользователя из настроек iMark. Стандартный пароль Администратора
-- 123, пользователя Касса -- 1.

По кнопке «Проверка авторизации в iMark» проверить корректность указания
параметров связи.

Далее необходимо выбрать уровни проверки.

1.  **Локальная проверка** по базе данных выполняется с целью выявления
    уже проданного по данным iMark без необходимости делать запрос в ГИС
    МТ и исключить продажу товара.

> Режим проверки «Нестрогая» - проверки по базе данных iMark будут
> игнорироваться и приоритет будет у данных из ГИС МТ.
>
> Режим проверки «Строгая» - проверки по базе данных iMark будут
> учитываться и при ошибках таких проверок (код маркировки уже числится
> проданным) будет запрещено продавать код маркировки и добавлять его в
> чек.

2.  **Проверка в ГИС МТ** -- Полученный в ответе от iMark набор
    реквизитов из ГИС МТ будет разобран на соответствие критериев и при
    ошибках проверки в «Нестрогом» режиме будет выведено уведомление с
    вопросом о добавлении товара с таким кодом в чек. А в «Строгом»
    режиме будет выведен перечень ошибок проверки с последующей
    блокировкой добавления кода маркировки в чек.

> В версии 5.1.3 обработки информация о продажах кодов маркировки пока
> не передается в базу iMark и будет добавлена в версии 5.1.4, поэтому в
> версии 5.1.3 рекомендуется переключать локальную проверку в режим
> «Нестрогая».

## Примеры уведомлений разрешительного режима
Уведомление о наличии ошибок проверки с блокировкой продажи (Проверка в
ГИС МТ -- строгая). Здесь клавиша 2 клавиатуры или Enter подтверждает и
закрывает окно.

![](/images/image126.png)

Вопрос о добавлении кода маркировки в чек при получении сведений о том,
что код уже продан (Проверка в ГИС МТ -- Нестрогая). Здесь клавиша 1
клавиатуры соответствует действию кнопки «Отказаться», а клавиша 3
клавиатуры -- действию кнопки «Добавить в чек».

![](/images/image127.png)
