# Пробитие чеков из кассовых ордеров

В кассовом чеке, сформированном, из документов \"Приходный кассовый
ордер\" и \"Оплата от покупателя платежной картой\" с видом операции
\"Оплата от покупателя\", а также из документа "Расходный кассовый
ордер" с видом операции "Возврат денежных средств покупателю" выводятся
подробные сведения о номенклатуре - наименование, количество, цена,
сумма, сумма НДС. Эти сведения заполняются или из сделки, или из
документа \"Реализация товаров и услуг\", указанного в качестве
документа расчетов.

Внимание! При работе в формате ФФД 1.0 необходимым условием для пробития
товаров в чеке является совпадение суммы оплаты в разрезе
сделок/документа расчетов. В случае если указана и сделка, и документ
расчетов \"Реализация товаров и услуг\", то в кассовом чеке сведения о
номенклатуре будут заполняться из документа расчетов (т.е. из
реализации).

При работе в Формате ФФД 1.05 возможны более гибкие и многообразные
варианты пробития чеков с указанием товаров или оплат за товары в чеке.

Поскольку при пробитии чека из указанных трёх документов в обработку
обслуживания не поступает прямой информации о том, откуда пробивается
чек, в обработке реализован механизм определения такого документа печати
следующим образом (при установленной настройке «Пробивать товары из ПКО,
РКО и ОПК»):

1.  Автоматический режим по журналу регистрации.

Данный вариант подразумевает, что обработка самостоятельно определит,
из какого документ пользователь пытается распечатать кассовый чек.
Никаких дополнительных действий пользователю выполнять не потребуется.

Для корректной работы данного автоматического срабатывания должны быть
соблюдены следующие условия:

-   **В конфигурации активировано ведение журнала регистрации.**

-   **В конфигурации заведены пользователи и чек пробивается от имени конкретного пользователя информационной базы.**

-   **Под одной учетной записью пользователя информационной базы одновременно работает не более одного пользователя.**

Для включения в информационной базе ведения журнала регистрации,
необходимо открыть базу данных в режиме Конфигуратор под пользователем
с полными правами.

Открыть меню "Администрирование" -- "Настройка журнала регистрации.."

В открывшемся окне в качестве минимального уровня ведения журнала
необходимо установить "Регистрировать ошибки, предупреждения,
информацию", но не ниже.

Другими словами, режим "Регистрировать ошибки, предупреждения" будет
недостаточным для автоматического механизма.

![](/images/image83.png)

**На представленном скриншоте активирован режим ведения всех событий в
журнале регистрации, включающий в себя регистрацию "информации",
которая необходима для работы автоматического режима.**

Если все эти требования соблюдены, то в 99.9% случаев кассовый чек
будет пробиваться корректно в автоматическом режиме.

::: warning Внимание
Перед пробитием кассового чека из документов \"Приходный
кассовый ордер\", \"Оплата от покупателя платежной картой\" и
"Расходный кассовый ордер" перед нажатием на кнопку «Чек» для пробития
кассового чека, документ необходимо обязательно провести вручную и
только после этого нажимать на кнопку «Чек». Пробитие чека
осуществлять только из открытой формы документа.
:::

2.  Автоматический режим по открытым окнам документов.

Если по каким-то причинам вы не можете активировать ведение журнала
регистрации в своей информационной базе, либо, если по каким-то
причинам, не сработал первый автоматический механизм, то будет
активирован второй механизм определения документа, из которого
пользователь пробивает кассовый чек -- поиск документа с открытым
окном. Период дат для поиска для такого документа задается равным
только текущей дате, поэтому если пробивать чек из документа не из
текущей даты, то такой метод поиска не сработает. Так же для этого
метода важно, чтобы форма документа, из которого осуществляется
пробитие чека, была открыта.

3.  Передача прямой ссылки на документ печати из конфигурации. 
Это самый надежный и точный метод, но требующий доработки конфигурации.
Доработку необходимо проводить согласно инструкции «Инструкция по
доработке конфигурации».

## Пробитие из ордеров в режиме «ККТ с передачей данных»

Если оборудование подключено как «ККТ с передачей данных», определять документ печати
обработке не требуется: конфигурация передаёт прямую ссылку на документ сама. Это тот же
третий, самый надёжный вариант из списка выше, но доработка конфигурации для него не нужна —
ссылку передаёт штатный механизм.

Ни журнал регистрации, ни открытое окно документа в этом режиме на определение документа
не влияют. Настройка «Пробивать товары из ПКО, РКО и ОПК» продолжает действовать: при снятом
флаге в чек уйдут только суммы, переданные конфигурацией, без товарных позиций из документа.

### Документ после пробития перезаписывается конфигурацией

После успешного пробития чека конфигурация записывает в документ номер чека и кассу ККМ.
Делает это она сама, отдельно от открытой формы документа, а форму при этом не обновляет.

Поэтому, если форма документа остаётся открытой, попытка записать или провести документ
из неё завершится сообщением о том, что данные были изменены другим пользователем.

Чтобы этого избежать:

-   проводите документ **до** пробития чека, как описано выше, и после пробития не
    записывайте его повторно;

-   если работу с документом нужно продолжить, закройте его форму без сохранения и откройте
    заново — записанные номер чека и касса подхватятся.

Это поведение самой конфигурации, одинаковое для обоих видов подключения оборудования.
Настройками обработки оно не регулируется.
